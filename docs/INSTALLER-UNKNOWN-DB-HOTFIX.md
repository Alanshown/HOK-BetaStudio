# 1.3 安装目录与未知 DB 修补

## 安装目录

旧脚本在 `.onVerifyInstDir` 中用 `IfFileExists "$INSTDIR\*.*"` 拒绝已存在目录。该回调也参与浏览对话框校验，导致选择文件夹时“确定”不可用；它并不能正确表达“只禁止覆盖文件”。

修补后：

- 可以选择当前用户有写入权限的自定义目录，包括已有空目录、中文／越南文／空格路径和含无关文件的目录。
- 点击安装时才检查安装文件清单中的同名冲突和写入权限；有问题显示明确提示，不静默覆盖文件。
- 保留禁止磁盘根目录安装的保护；安装仍为当前用户安装，不自动提权。
- 交互安装和静默 `/S /D=...` 安装使用同一个校验函数。
- 卸载仍按精确清单删除本程序文件，不递归删除用户后来放入的其他内容。
- 安装器与程序内部文件版本为 `1.3.0.2`，程序显示版本仍为 `1.3`。

若目标文件夹中已有旧版程序，请先卸载旧版，或选择新建的程序子目录；本修补不加入覆盖升级功能。

## 未知 DB

英雄号只决定分类，不再作为 DB 导入条件。所有非空名称的 `.db` 文件均可进入扫描结果；没有 `.db` 扩展名的文件仍需通过受支持容器签名检查。

- 数字名称满足原有英雄号规则时，继续使用英雄／皮肤视图。
- `0.db`、`0_0.db`、`自定义包.db` 等显示为“未知 DB 文件”列表，不伪造英雄编号。
- 主包与 `_数字` 分片按实际所在目录和文件名前缀配对；不同子目录中同名的包不会合并。
- 仅导入未知包时直接显示列表；混合导入时与英雄卡片并存。
- 复用相同的 Worker、资产表、筛选、预览、批量导出、Beta 替换／重建流程。支持的格式和实验性限制不因分类改变。
- 解析失败的内容按原有规则保留为原始条目并记入诊断；“未知分类”不代表自动支持任何新压缩算法或序列化版本。
- Worker 标准输入／输出显式使用 UTF-8，避免中文路径受系统代码页影响。

## 验证与打包

```powershell
pwsh -NoProfile -File tooling/test-installer-paths.ps1
.\.tools\dotnet\dotnet.exe run --project backend/Hok.Contracts.Tests -- .
node tooling/test-unknown-db.cjs '你的未知DB目录' 'build/HOK-BetaStudio-1.3-hotfix-win-x64'
```

安装路径回归运行真实 NSIS 校验代码，但不创建快捷方式或安装注册表记录。资产回归使用隔离数据目录与原始文件 SHA-256 检查；不会覆盖原包。

合并嵌套资源发现修复后，实测一组 `0.db`／`0_0.db` 读取 38,992 条资产与容器记录，包括 274 条 WwiseAudio 和 4 个 WwiseBank。仍有 34 条底层解析诊断，包括 26 个保留为原始数据的压缩条目；部分图片的外部资源无法解析，不能宣称全部图片均可预览。将完全相同的数据改成英雄号文件名后，条目数、类型统计与诊断数量相同，证明这些限制不由未知分类引起。

与英雄包一样，存在底层解析错误的包不能通过 Beta 替换／重建的完整性校验；不会为了允许“未知”分类而绕过这项保护。

另将已验证的 10500 原皮包复制并重命名为中文自定义名称，读取 879 条记录、无解析错误，用于验证贴图与模型功能不受分类影响。部分读取与仅原始对象仍按各自状态显示，不代表所有结构均已解释。

该中文命名副本还通过了实际原始贴图流替换、完整 Beta 回包、重新导入及替换数据逐字节核对。原始 DB 未改变；这仍不等于游戏内兼容性验证。

```powershell
pwsh -NoProfile -File tooling/build-desktop.ps1 `
  -OutputDirectory build/HOK-BetaStudio-1.3-hotfix-win-x64 `
  -NativeDirectory .tools/native/x64

pwsh -NoProfile -File tooling/package-desktop.ps1 `
  -BuildDirectory build/HOK-BetaStudio-1.3-hotfix-win-x64 `
  -OutputDirectory deliverables/release-1.3-hotfix
```

仅重做安装器时可添加 `-InstallerOnly`。输出目录需避免覆盖已有安装器。

这份修补的安装器和 ZIP 有新的 SHA-256；不能沿用最初 1.3 Release 的校验值。旧的已发布文件和校验文档不在本地修补时自动替换，公开发布前需同步更新附件及其校验值。

## 资源发现与动画修复验证

选择性合并 `hok-discovery-source-fixes.zip` 的读取器与诊断改动，未引入 Linux 运行器、解码缓存、第三方二进制或测试用游戏资源。

- 展开连续的 SerializedFile，保留原始容器与切片偏移。
- 以对象表作为列表依据；解析失败仍保留原 classID、PathID、来源、原始字节和原因。
- 显示完整读取、部分读取、仅原始对象、失败等状态，以及未解释字节和诊断截断提示。
- 按来源和容器区分同名文件；对象读取不能越界影响后续对象。
- 适配 HOK 压缩动画，并补齐 Windows `.anim` 与 FBX 转换管线对 `m_HokLegacyAnimation` 的支持；重复导出不会累加曲线。
- 修复零位宽常量顶点色，保留完整索引记录与包信息。
- Beta 替换仅接受完整读取的对象；嵌套对象替换使用原始容器偏移，索引元数据不可替换。

19306 样本：196 个序列化文件、3685 个对象；108 张贴图全部导出 PNG、85 个网格全部导出 OBJ、12 个动画全部导出 `.anim`。四个旧式动画的全部绑定均进入导出曲线，且通过 FBX 模型转换层测试（未做游戏内运行验证）。全部对象原始范围逐字节匹配；231 条索引／包记录共 12112 字节，包信息为完整 116 字节。

```powershell
.\.tools\dotnet\dotnet.exe run --project backend/Hok.Discovery.Tests -- . '完整19306样本目录'
node --experimental-strip-types --test frontend/tests/diagnostics.test.mjs
node tooling/test-discovery-worker.cjs '构建目录' '完整19306样本目录' '上一步输出的scratch目录'
```

真实样本测试需要将合法取得的原生解码库放到测试输出目录的 `x64` 子目录。合成测试只传项目根目录即可运行，不需要游戏数据。

详细统计见 `DISCOVERY-FIX-VALIDATION.json`。安装路径测试使用实际 NSIS 代码，但不代替每台电脑上的交互安装；无写入权限、磁盘根目录和会覆盖其他文件的位置仍会被明确拒绝。
